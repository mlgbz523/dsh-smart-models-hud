# dsh-smart-models — 智能模型聚合选择器 + 渠道积分 HUD

> 专为 DeepSeek Harness (DSH) 打造的独立规范级 Cordis 插件，同时解决两个痛点：
> **① 模型选择器中渠道过多、模型分散、翻找繁琐；② 看不到各免费渠道的实时积分余额与单轮消耗。**

- **仓库名**：`dsh-smart-models-hud`
- **包名（package.json `name`）**：`dsh-smart-models`
  > 两者不同是刻意为之：保持包名不变可让已有本地 profile 依赖与软链接零改动。

---

## 📥 安装

### 方式 A：从 Release 下载（推荐）

1. 打开 [Releases](https://github.com/mlgbz523/dsh-smart-models-hud/releases) 下载 `dsh-smart-models-0.1.0.tgz`；
2. 解压到 `~/.dsh/profiles/desktop/node_modules/dsh-smart-models/`；
3. 在 `~/.dsh/profiles/desktop/package.json` 的 `dependencies` 加入：
   ```json
   "dsh-smart-models": "file:node_modules/dsh-smart-models"
   ```
4. 在 `dsh.profile.bundles` 数组末尾加入 `"dsh-smart-models"`；
5. **完整重启 DSH**（宿主层改动，`Ctrl+R` 不够）。

### 方式 B：clone 后软链接

```powershell
git clone https://github.com/mlgbz523/dsh-smart-models-hud.git
cmd /c mklink /J "%USERPROFILE%\.dsh\profiles\desktop\node_modules\dsh-smart-models" "<clone路径>"
```

之后同方式 A 的第 3–5 步。

## 🌟 核心特性

### 一、模型聚合选择器

1. **以模型为中心（Model-centric 聚类）**：
   - 告别按渠道拆分的冗余模型列表。同名模型（如 `DeepSeek-V4.1-Flash`、`Gemini 3.8 Flash`、`DeepSeek-R1`）整齐聚类为单一行。
   - 右侧直观展现该模型在各供应商渠道的药丸徽章及精准计费倍率（精确到两位小数，如 `x0.00`、`x0.50`、`x1.00`）。

2. **左侧模型列表 + 右侧动态伴随渠道卡片**：
   - 左侧单行高度锁定 32px，零布局跳动（Zero Layout Shift）。
   - 鼠标滑过模型行，右侧伴随卡片跟随 Y 轴动态对齐，自动避让屏幕边缘。

2.4. **按渠道商分类视图（可切换，默认「按模型」）**：
   - **默认进入「模型」视图**；存量用户若曾被保存为「渠道」，升级后会**一次性重置**回「模型」
     （之后你手动切到渠道仍会被正常记住，不会被反复重置）。
   - 底部思考档位栏**最右端**有一个**单按钮两态开关**：默认显示 `模型`（中性描边），
     点击后变为 `渠道`（紫底白字），与思考档位胶囊同一视觉语言，最大程度压缩面积。
   - 切到「渠道」后，主卡片每行是一个**渠道**（渠道名 + 剩余额度 + 模型数），
     **不再内联展开**——鼠标悬停某渠道行，右侧弹出**伴随卡**列出该渠道的全部模型，
     与「按模型」视图的伴随卡完全同构（同样的位置计算、翻转避让、150ms 宽限、隐形桥接通道）。
   - 伴随卡每行 = **模型名 + 计费倍率 + 健康状态点**；当前正在使用的那行高亮并带 `使用中` 徽章，
     点击即切换到该渠道该模型。渠道已由悬停确定，故这里**不显示渠道星标**（星标属于模型维度）。
   - **渠道行右侧显示该渠道剩余额度**：积分型渠道显示跨账号累计积分（如 `1,840 分`），
     配额型渠道（Gemini / agy）显示 5h/周窗口的**最低剩余百分比**（如 `62%`，百分比不可跨账号相加）。
   - **受控并发拉取**：进入渠道视图即全量查询余额，但走**并发度 2** 的任务池，
     每完成一个渠道就立即更新该行——界面**渐进填充**而不是等全部结束。
     优先调用 `usage.badge`（channel-pack 自带 **120 秒服务端缓存**，重复进入几乎零成本），
     旧版渠道包缺该 RPC 时自动回落 `credits.balances`。
   - **单位统一**：服务端下发的 `credit` / `credits` / `积分` 全部归一显示为 **分**；
     `token` / `USD` 保持各自量纲。配额型渠道（agy / Gemini）显示 `%`——
     百分比与积分不是同一量纲，**不做强行换算**。
   - **余额列定宽右对齐 + 等宽数字（tabular-nums）**，所有行的数字严格成列对齐。
   - **默认排序**（2026-10-20 按用户指定）：
     `agy` / `Google Gemini` 最前 → 国内大厂积分渠道（WorkBuddy 国际、TRAE、讯飞 Loomy、CodeArts、WorkBuddy 国内）→
     其余第三方 → `LobsterAI(有道)` / `Qoder` 下调 → `官方账号` / `Siliconflow` 置底。
     可在 **设置 → 渠道排序** 用 ↑/↓ 覆盖，结果同时写入 localStorage 与磁盘偏好。
   - **行→伴随卡的可靠性**：关闭宽限为 **320ms**（150ms 实测不够，斜向移动常赶不上），
     且伴随卡带**竖向隐形桥接通道**覆盖对角线路径——因为伴随卡会被视口钳制，
     可能与悬停行相差几百像素，只覆盖水平走廊挡不住斜向移动。
   - **当前模型的家族默认展开**：打开面板就能看到自己在用的模型及其同族兄弟，不必先点家族标题；
     其余家族保持折叠（手风琴互斥单开）。自动展开的家族**不吸顶**，只有手动点开的才吸顶。
   - **伴随卡「第一个选项」与母行中线严格对齐**（不是卡片头部对齐）：
     定位时补偿了头部标题栏 32px + 列表内边距 6px 的偏移，使第一张渠道卡的中线与悬停行中线重合。
     头部高度与选项卡高度在 CSS 中锁死（32px / 29px），与 JS 常量 `FLYOUT_OPTION_OFFSET_PX` /
     `FLYOUT_OPTION_ROW_PX` 一一对应，避免字体渲染差异造成累积误差。
   - **空间不足时降级**：母行贴近视口顶部/底部时，放弃选项级对齐、改为整卡位移，
     优先保证卡片完整可见（此时内容超出靠**卡片内部滚动**消化）。卡片高度上限 460px。
   - 渠道视图**不设置顶区**：星标是模型级收藏，在渠道维度没有等价物；
     当前会话所在的渠道行以左侧青色标记 + 高亮渠道名标识。
   - 面板底栏为**常驻 footer**：思考档位胶囊按需渲染，视图开关永远存在——
     否则切到 Claude / GPT-OSS 这类无思考档位的模型时，开关会随整行消失，用户再也切不回来。

2.5. **家族折叠分组（应对海量模型）**：
   - 面对 75 个 provider、500 个模型时不再平铺成一张长列表：
     - **星标模型 + 当前使用模型** 置顶展示，始终展开
     - 其余按**模型家族**折叠（GPT / Qwen / DeepSeek / Kimi / GLM / Claude / Gemini / Llama / MiMo / Grok / MiniMax / Doubao …），默认全部收起
   - 实测：500 条原始条目经命名归一后降为 **305 个模型**，折叠为 **19 个家族块**
   - 模型数少于 3 的小家族自动并入「其他模型」，避免标题行过多
   - **搜索时自动平铺**，不做分组（搜索本就是精准定位）

3. **星标（★/☆）独立收藏与默认渠道设置**：
   - **模型级收藏**：模型名前隐藏式星标，激活时显示实心金星，未激活时鼠标悬停显示空心开关。
   - **渠道级星标**：将该渠道设为该模型的永久首选渠道。
   - 星标操作为纯收藏记忆，**绝不改变当前会话的即时模型**，防误触。

4. **智能最低消耗推荐与点击直连**：
   - 为每个模型自动计算积分/倍率最低的渠道（免算力通道 > 每日签到积分 > 网页端额度 > API 按量扣费）。
   - 直接点击模型行即可一键使用该默认渠道。

5. **本地磁盘双重持久化**：
   - 偏好设置通过 `/api/smart-models/preferences` 同步到 `~/.dsh/smart-models-preferences.json`，清缓存也不丢。

### 二、渠道积分 HUD（输入框左侧常驻胶囊）

> 设置页分区：**Smart Models**（order 36，单入口，即插件本名）——原「用量统计 / 上行自检 / 渠道排序」
> 三个分区已合并为一个，内部用标签页切换，设置侧栏只占 1 行（原 3 行）。
> 「渠道排序」标签决定「按渠道」视图里各渠道行的先后顺序，可覆盖内置的优先序。


6. **自动跟随当前渠道展示余额**：
   - 切到 `CodeArts` / `WorkBuddy` / `TRAE` / `LobsterAI` / `Qoder` 等积分渠道，自动显示该渠道所有账号的**积分总余额**（如 `🅲 CodeArts 1,360 分`）。
   - 点击胶囊可强制刷新。

7. **区分「积分型」与「配额型」两种语义**（重要）：
   - **积分型**（codearts/buddy/trae/lobsterai/qoder/minimax/zcode…）：跨账号累加，显示总积分。
   - **配额型**（`Gemini` 5小时/周窗口、`Antigravity agy` 5小时/周窗口）：**取最低剩余窗口百分比**，不累加（百分比相加无意义），并按健康度着色（≤10% 红、≤30% 琥珀）。
   - 悬停胶囊可查看各窗口分别剩余与重置时间。

8. **任务结束自动结算消耗**：
   - 任务开始时快照余额，结束后强制重查并计算差值，胶囊短暂显示 `⚡ -X 余 Y`，8 秒后回落。

9. **数据来源只读解耦**：
   - 积分型与 Gemini 走 `dsh-our-free-model` 的 `channel-pack` RPC（`credits.balances`）；
   - agy 走本插件宿主路由 `/api/smart-models/agy-quota`（读取 `~/.dsh/agy-accounts/pool.json`）；
   - **不修改、不侵入上述插件的任何源码与状态**。

## 📦 插件架构与规范

- **Cordis 微内核架构**：零侵入，注册两个槽位：
  - `conversation.input.model`（模型选择器，并自动禁用原生选择器）
  - `conversation.input.left`（积分 HUD）
- **纯前端 + 轻量宿主路由**：复用宿主 React runtime 与 CSS 变量；宿主端仅提供三个同源只读路由：
  - `/api/smart-models/preferences`（偏好读写）
  - `/api/smart-models/channel-status`（签到状态）
  - `/api/smart-models/agy-quota`（agy 窗口额度）
- **无外部二进制、无重量构建依赖**。

## 🩺 上行自检（设置页）

打开 **设置 → Smart Models → 上行自检标签**，或直接看模型选择器里每行右侧的小圆点。

解决的问题：模型「选中即失败」时，你只能等聊天区吐一条红字，而且**不知道原因属于哪一类**——是额度用完了、还是这个模型在这个渠道被限制了、还是上游根本不认这个模型 id。三者的处置完全不同（领积分 / 换模型 / 换账号）。

### 三层信号

| 层 | 检查什么 | 需要网络？ | 消耗额度？ |
|---|---|---|---|
| **模型级限制** | 渠道包已落盘的 `modelRateLimits`（按 **账号 × 模型** 记录） | 否 | 否 |
| 渠道与账号 | 账号启用状态、失效模型表、用户关闭表 | 否 | 否 |
| 观测到的请求 | `token-ledger.json` 的请求数与错误数（含失败率） | 否 | 否 |
| **主动探活** | 真向每个账号发一次最小请求 | 是 | **是** |

> [!IMPORTANT]
> **前三层零成本，默认全开。** 数据全部来自本机已存在的文件，接口 `GET /api/smart-models/uplink-health` 只读盘、不发网络请求。

### 为什么「模型级限制」比「额度」更该先看

额度是**账号级**的（这个账号还有多少积分），限制是 **(账号 × 模型) 二元组** 的：

- 同一个账号可以对这个模型受限、对那个模型正常；
- 同一个模型可以在 5 个账号里有 4 个受限。

只报「额度耗尽」会把「换一个模型就能跑」误报成「没额度了」。选择器上的圆点与提示因此以限制优先：

```
● 1/5 个账号受限 · 最早 16 小时 39 分后恢复
● 全部启用账号均受限 · 最早 38 分钟后恢复
● 上游拒绝该模型 id（Invalid model.）· 10-19 23:41
```

圆点颜色：绿 = 正常，琥珀 = 部分受限/失败率高，红 = 全部受限或已判失效，灰 = 未知。


### 第四种状态：会员 / 订阅墙

除了「受限」「不可用」「未知」，还有一类**不会随时间恢复、充值也无效**的失败：模型属于某个**订阅通道**，必须先开会员。

离线可判的依据是模型 id 的命名空间前缀（插件把远端目录原样播报）：

| 前缀 | 含义 | 处置 |
|---|---|---|
| `cline-pass/<id>` | Cline 订阅通道（`pack.js:41521` 由 models.dev 补入，`41553` 显式 `isFree: false`） | 去 Cline 开会员，或换渠道 |
| `cline-free/<id>` | Cline 免费池（`pack.js:41287`） | 正常可用 |

选择器上这类模型显示**紫色圆点**，悬停提示「该模型属于 Cline 的订阅通道…充值积分或换账号都无效」；渠道卡片显示「会员」标签。

> [!IMPORTANT]
> **不靠 `isFree === false` 推断会员墙。** 那只说明「不是免费」，按量计费的模型同样是 `false`。把两者混为一谈会让每个付费模型都挂上「需开通会员」的假标签。只有确凿的命名空间前缀才判定。

上游返回的文字也会归类（`classifyUpstreamMessage` → `subscription-required`），覆盖：

- `requires … subscription` / `plan required` / `not subscribed`
- `upgrade to Pro/Plus/Premium` / `premium only` / `paid plan only`
- 中文「需开通会员」「订阅专属」

⚠️ 这一分支**必须排在额度判定之前**：`402` 既可能是「积分不足」也可能是「付费墙」，而两者处置相反。带订阅字样的优先归订阅。
### 数据来源

| 文件 | 用途 |
|---|---|
| `~/.dsh/channel-pack/state.json` | 账号启用状态、`modelRateLimits`、`disabledModels` |
| `~/.dsh/channel-pack/token-ledger.json` | 请求数与错误数（key 为四段：调用方式、provider、账号、模型） |
| `~/.dsh/channel-pack/dead-models.json` | 已被判定失效的模型（文件可能不存在，属正常） |
| `~/.dsh/channel-pack/auto-checkin.json` | 今日签到领取结果 |
| `~/.dsh/our-free-model/stats.json` | 免费车道的每模型调用数与失败数 |

**脱敏**：接口只回聚合量与模型 id，**不回** `credentialRef`、账号昵称、AK/SK。

### 两个按钮

- **重置限流**：调用 `channel-pack` 的 `account.resetAll`，只清**本机**的 `modelRateLimits` 记录，**不发网络请求、不改变上游真实限制**。用于「服务端已放行、本机还记着旧时间」。
- **探活**：向该渠道的每个账号**串行**发一次最小对话请求（`account.test`），单账号超时 120 秒、可随时中止。**会真实消耗上游额度**，按钮上已标注。结果只显示在界面上，不写任何文件。

### 已知边界

- 主动探活的消耗量由上游默认输出决定，**不可预估**。
- 「失效模型」表依赖上游文案被识别为「模型已下线」。部分上游（如华为云 `Invalid model.`）不在渠道包的识别规则内，因此这类模型**不会**进失效表——本插件改用请求台账的失败率来暴露它。
- 限制标记是「上次失败时的快照」，服务端常在重置时间之前就放行；因此界面显示的是「最早恢复时间」而非「一定不可用」。

## ⚠️ 已知限制

- **多账号渠道首次查询较慢**：上游 `credits.balances` 是串行逐账号查询，单账号超时 30 秒。3 个账号的渠道最坏需 90 秒。已通过 60 秒结果缓存缓解（切换回来秒开），强制刷新仍会等待。
- **部分渠道无积分概念**：如 `Siliconflow`、官方 API 等按量扣费渠道，HUD 会自动隐藏或显示 `—`。
- **上行自检的模型级限制依赖渠道包落盘**：若未安装 `dsh-our-free-model`（或未启用渠道包），自检页只显示空表，不报错。
- **探活是唯一会消耗额度的动作**：它不在挂载、切换模型或刷新时自动触发。

## 📊 用量统计（设置页）

打开 **设置 → Smart Models → 用量统计标签**，可查看：

- **按模型** / **按渠道** / **按日期** 三个维度的汇总
- 每项包含：请求数、Token、消耗积分、换算≈token
- 时间范围切换：今天 / 近 7 天 / 近 30 天 / 全部

### 数据从哪来

| 数据 | 来源 |
|---|---|
| 积分消耗 | **本插件自己观测**：每轮任务开始时快照余额，结束时重查并计算差值，写入 `~/.dsh/smart-models-usage.json` |
| Token | 同一轮次记录的 input/output token |

> [!IMPORTANT]
> **积分统计自本功能安装后开始累积**。
> DSH 现有的 `token-ledger.json` 与 `stats.json` 只有 token 计数，**从未记录过积分**，因此历史积分消耗无法回溯。页面顶部会标注实际起始日期。

### 独立 Web 看板（全量追溯）

设置页保留全部统计内容，另外提供一个**只读 Web 看板**用于全量追溯：

- **地址**：`http://127.0.0.1:<DSH端口>/smart-models`
  设置 → Smart Models → 用量统计 → 右上角「打开完整看板 ↗」直接跳转
- **能力**：时间范围（今天/7天/30天/全部）· 渠道筛选 · 模型筛选 · 仅可信记录 ·
  关键词搜索 · 明细分页（100 条/页）· 点柱状图某天即过滤当天 ·
  按渠道/按模型汇总（按积分降序）
- **零依赖单页**：`dashboard/index.html`，内联 CSS/JS，不引用任何外部资源，离线可用
- **只读**：看板不做任何写操作（清理仍在设置页）；数据来自同一个
  `/api/smart-models/usage` 接口
- **不新开端口**：复用宿主 `webServer`（其本身只绑回环地址），
  路由 `kind:'exact', path:'/smart-models'`

> 为什么不自起端口：`our-free-model` 自起端口是因为它要对外提供 OpenAI 兼容 API
> （必须独立端口 + 自建密钥）。看板只是只读页面，挂宿主端口零额外风险。

### 明细日志与每日图表（v0.2 新增）

- **明细日志表**：每轮一行——时间（HH:mm:ss）· 渠道 · 模型 · 积分 · 标记。
  可疑轮次带「渠道切换」「账号变化」灰字标记（积分列显示 —）。默认最近 50 条，可展开全部。
- **每日积分柱状图**：纯 SVG 自绘（零新依赖），只计可信记录；悬停柱体显示 日期·积分·请求数。
- **清理历史可疑记录**：一键把历史垃圾（单轮 >1000 积分或带可疑标记）改写为不可信，
  执行前自动备份 `smart-models-usage.json.bak`。本机实测：192 条事件中 9 条垃圾、
  共 **111,930 假积分**将被剔出聚合统计。

### 误算修复（结算三道闸）

旧结算只存余额数字，`before - after` 在跨渠道/账号集变化时产生假消耗
（真实台账出现过单轮 -8000 与 15159.99 的垃圾记录）。现在：

1. 快照升级为对象 `{total, provider, accounts}`，渠道切换即失效并重新快照；
2. 结算经 `settleRound` 三道闸：**渠道变了 → 弃积分**（`suspect:'provider-switch'`）、
   **账号集变了 → 弃积分**（`suspect:'account-change'`）、**余额增加 → 记 0**（签到场景）；
3. 可疑轮次 HUD 不再显示 `-X`；台账仍记请求数（`creditsKnown:false`），统计完整性优先。

### 关于「换算≈token」

换算比例是按**当前范围内实测均值**反推的（累计 token ÷ 累计积分），**不是官方汇率**：

- 不同渠道计费规则不同（按 token / 按次 / 按积分包）
- 样本量少时比例波动较大
- 累计积分为 0（全程使用免费渠道）时，换算列显示 `—`，不会编造数字

### 数据保留

台账只保留最近 **90 天**事件，超出部分自动裁剪，避免文件无限增长。文件损坏时会自动重建空台账而非报错。
